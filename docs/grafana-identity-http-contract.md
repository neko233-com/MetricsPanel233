# Grafana identity HTTP contract notes

Status: source audit and implementation requirements, 2026-10-13. Baseline is **Grafana v13.2.3 OSS**. This supplements [the identity design](grafana-identity-design.md). It does not certify the new native identity catalog as a complete Grafana authentication implementation. Native credentials currently use `mp233_session_` / `mp233_sa_` opaque formats; these are not Grafana token encodings. HTTP authentication, authorization, organization dispatch and PC login are separate acceptance steps. Enterprise custom RBAC, SAML, SCIM and Enterprise datasource permissions are excluded here.

## Implemented request adapter, opt-in

`internal/instance.HTTPAuthenticator` now validates Basic human passwords, native service-account Bearer tokens, Basic `api_key` token credentials and native browser-session cookies against the actual persistent catalog. It binds the credential privately to the request's typed identity and selected organization; resource permission callbacks and selected route authorizers revalidate that original credential. Looking up a live user ID, supplying an old role or placing a local/system principal in request context does not authenticate a request. Organization selectors cannot add memberships or move a service-account token. Native namespace precedence uses the already implemented `default` / `org-ID` mapping; Grafana stack-namespace formats remain pending.

The adapter defaults to cookie name `grafana_session` and a ten-minute native rotation gate, both configurable at construction. It does not issue cookies or expose a login screen. An overdue session returns 401, including when its rotation deadline passes between initial dispatch authentication and the selected route's second check. Session/token revocation, password changes, current roles and organization state are rechecked; metadata exposes only the authentication method and the actual authenticated session ID. A valid cookie cannot rescue an invalid explicit Authorization header; repeated Authorization headers or repeated matching session cookies are rejected. This ordering deliberately differs from Grafana's configured-client fallthrough.

Foreign Origin or cross-site fetch requests fail before session last-seen/token-seen writes. Origin comparison uses the actual transport scheme and host; untrusted forwarding headers cannot override it. Configurable trusted reverse-proxy origin/subpath handling has not yet been implemented.

`NewProtectedOrganizationHandler` resolves the authenticated principal to the physical organization server. It refuses a nil, legacy or different authorizer with 503, and permits authenticated Role None identities to reach explicit action/resource checks. Every child must be configured with the exact immutable credential authorizer before its Handler is built. The CLI still mounts the existing single-workspace service: the new handler is not activated until the complete action matrix, permission migration/readiness, list/body filtering, plugin lifecycle and Live revocation/cache boundaries are implemented and verified.

`NewCurrentUserHandler` independently provides these real signed-in operations:

| Route | Implemented behavior |
| --- | --- |
| `GET /api/login/ping` | Revalidates human or service-account credentials and returns 200; missing/revoked/invalid credentials return 401. |
| `GET /api/user` | Returns the local human's actual profile, immutable UID and UTC timestamps. A temporary request organization selector does not change persisted profile `orgId`. |
| `GET /api/user/orgs` | Lists only that human's active memberships in active organizations, with current roles. |
| `GET /api/user/auth-tokens` | Lists that human's available devices. The active ID comes from the private credential binding; Basic authentication has no active browser device. No credential, digest or raw User-Agent is returned. |
| `POST /api/user/revoke-auth-token` | Atomically verifies target ownership/availability and revokes the device. The active cookie device is 400; foreign/absent/expired/revoked targets are indistinguishable 404s. Revocation survives restart. |

The four user routes currently support local humans only: service-account callers receive 403 before body parsing, including equal numeric human/account IDs. Grafana's reduced service-account profile and its 304 human-helper oddities remain unimplemented. Native revocation retains a private tombstone and excludes unavailable devices rather than exposing Grafana's hard-deletion semantics. Body parsing is limited to 64 KiB, one JSON object, known fields and exact int64 IDs; these stricter validation rules are native behavior. Unknown identity administration/preferences/login routes remain absent.

Device DTOs use the exact Apache-2.0 `uap-go` version pinned by Grafana 13.2.3, major/minor versions and local-password auth-module mapping. Tests use real persistent SQLite catalogs and real HTTP requests, including Windows Edge metadata, cookie persistence after reopen, typed identity separation, organization isolation, changed/revoked credentials, unknown-route denial and origin-before-write behavior. They do not establish PC login, cookie issuance/rotation responses, all identity APIs or whole-product Grafana compatibility.

## Authentication and browser entry

| Request | Pinned behavior to implement or explicitly track |
| --- | --- |
| `GET /login` | Returns the login HTML for an unauthenticated browser; a signed-in browser is redirected to the application. Respect disabled login-form configuration and the application subpath. |
| `POST /login` | JSON `{user,password}`; `user` is the login or email. Success is **200** `{message:"Logged in",redirectUrl}` with the session cookies. Missing/invalid form is **400**; rejected password and login-attempt blocking are **401**. Passwords and issued session values do not appear in the response JSON. |
| `GET /api/login/ping` | **200** `{message:"Logged in"}` when authenticated; otherwise **401**. |
| `GET /logout` | Revokes the browser session, deletes its cookies and redirects to the configured logout destination; ordinary local login returns to `/login`. It is a browser redirect, not a JSON logout endpoint. |
| `POST /api/user/auth-tokens/rotate` | Uses the browser session cookie; **200** `{}` plus replacement cookies. Invalid/absent session gives **401** and may clear the invalid cookie. |
| `GET /user/auth-tokens/rotate` | Browser redirect counterpart, returning to the validated application location after rotation. |

These paths are outside the `/api/user` signed-in group. Source: [route registration](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/api.go), [login handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/login.go), [form authentication](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/clients/form.go), [session response/cookies](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/authn.go), [rotation handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/user_token.go).

The default session cookie is `grafana_session`, with HttpOnly; `grafana_session_expiry` is intentionally readable by the browser and contains the next rotation time. Cookie name, application path, Secure, SameSite, absolute lifetime, inactivity lifetime and rotation interval come from server configuration. The expiry hint is not authorization. The server validates the session and reloads current identity/permissions. [Session client](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/clients/session.go), [cookie writer](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/authn.go).

Basic username/password authenticates a human identity; the documented automation path for global user/admin APIs uses Basic. Browser admin sessions also pass the registered identity/permission middleware: there is no general Basic-only check in these handlers. Bearer service-account tokens authenticate organization-local identities. The token client also recognizes Basic username `api_key` with the token as password; this must not accidentally become a human login. Expired, revoked, invalid and foreign-organization tokens are rejected with **401**. Legacy API keys unassociated with a service account are rejected. [Basic client](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/clients/basic.go), [token client](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/clients/api_key.go), [documented authentication](https://github.com/grafana/grafana/blob/v13.2.3/docs/sources/developer-resources/api-reference/http-api/authentication.md).

Unauthenticated API requests return **401** rather than login HTML; authenticated requests without the required grant return **403**. Browser page requests redirect to login when unauthenticated. Errors are not universally the native `{error:{message,status}}` envelope: legacy handlers commonly expose `message`, while typed errors add `messageId` and `statusCode`. The authentication service tries other configured clients after ordinary failures, but stops on token-rotation requirements. If MetricsPanel233 chooses to reject an invalid explicit Authorization header even when a valid cookie is present, record that stricter behavior as an intentional difference. [Middleware](https://github.com/grafana/grafana/blob/v13.2.3/pkg/middleware/auth.go), [authentication ordering](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/authnimpl/service.go), [typed errors](https://github.com/grafana/grafana/blob/v13.2.3/pkg/apimachinery/errutil/errors.go).

PC login must submit with Enter, show a plain localized error without clearing the username, keep the password out of URLs/storage/logs, and return to a validated internal dashboard URL. Grafana's default-password change/skip screen is a frontend branch after successful login, not a different success status. Its controller also supports reset-code recovery. OAuth/LDAP/auth-proxy/JWT, recovery mail, signup/invites and external-session behavior require separate implementations and tests; a password form does not establish these features. [Login page](https://github.com/grafana/grafana/blob/v13.2.3/public/app/core/components/Login/LoginPage.tsx), [controller](https://github.com/grafana/grafana/blob/v13.2.3/public/app/core/components/Login/LoginCtrl.tsx).

## Current human user and instance administration

The profile object uses numeric `id`, string `uid`, `login,name,email,theme,orgId,isGrafanaAdmin,isDisabled,isExternal,isExternallySynced,isGrafanaAdminExternallySynced,authLabels,createdAt,updatedAt,avatarUrl,isProvisioned`, with optional `accessControl`. Timestamps in the Grafana DTO are RFC3339 values, not native millisecond integers. Search hits use `isAdmin`, not `isGrafanaAdmin`. [Profile/search models](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/user/model.go).

| Route | Request and successful response | Required distinction / failures |
| --- | --- | --- |
| `GET /api/user` | **200** profile of the authenticated principal | The handler also returns a reduced profile for non-human identities; it does not make a service account a human user. |
| `PUT /api/user` | `{name,email,login,theme}` → **200** message | No password, organization role or server-admin grant is writable through this payload. Duplicate login/email updates return **409**. |
| `GET /api/user/orgs` | **200** `[{orgId,name,role}]` | Human memberships only. |
| `GET /api/user/teams` | **200** current-organization team DTO array | Human identity and organization scoped. |
| `PUT /api/user/password` | `{oldPassword,newPassword}` → **200** message | Check the old credential and password policy; externally synchronized credentials cannot be locally reset through this path. |
| `GET /api/user/auth-tokens` | **200** device/session metadata array | Human only; no session secret or digest. Each item includes `id,isActive,clientIp,device,os,osVersion,browser,browserVersion,authModule,createdAt,seenAt`. |
| `POST /api/user/revoke-auth-token` | `{authTokenId}` → **200** message | Bind to the current user; another user's token is absent. Current active token cannot be revoked here (**400**); logout is separate. |
| `GET /api/users` | **200** search-hit array | Instance user read permission; human server administrator is the ordinary OSS caller. |
| `GET /api/users/search` | `query,perpage,page,sort` → **200** `{totalCount,users,page,perPage}` | Defaults page1/perpage1000; maintain deterministic sorting and total count before pagination. |
| `GET /api/users/:id` | **200** profile | Malformed ID **400**, absent user **404**. UID resolution is also registered for this route family. |
| `GET /api/users/lookup` | `loginOrEmail` → **200** profile | Instance-wide lookup, not organization-member lookup. |
| `PUT /api/users/:id` | `{name,email,login,theme}` → **200** message | Instance user write permission; does not silently grant instance administration. |
| `POST /api/admin/users` | `{login,email,name,password,orgId?}` → **200** `{id,uid,message}` | Duplicate user is **412**, not the update route's **409**. `orgId` is an assignment request governed by server configuration. |
| `PUT /api/admin/users/:id/password` | `{password}` → **200** message | Admin reset; revokes all browser sessions. Disabled local login form or externally managed credentials can reject the reset. |
| `PUT /api/admin/users/:id/permissions` | `{isGrafanaAdmin}` → **200** message | Distinct from organization Admin; cannot remove the last Grafana administrator (**400**). |
| `POST /api/admin/users/:id/disable` / `enable` | **200** message | Disable revokes existing sessions; external-user constraints apply. |
| `POST /api/admin/users/:id/logout` | **200** message | Revokes all sessions; attempting to logout oneself through this admin route is **400**. |
| `DELETE /api/admin/users/:id` | **200** message | **404** if absent; remove memberships, teams, preferences, grants and sessions as well as the user record. |

Sources: [user handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/user.go), [admin handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/admin_users.go), [session/device handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/user_token.go), [legacy API documentation](https://github.com/grafana/grafana/blob/v13.2.3/docs/sources/developer-resources/api-reference/http-api/api-legacy/user.md), [request forms](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/dtos/user.go).

Pinned oddity to track instead of inventing successful behavior: several human-only helpers return **304** for a service-account caller (`/api/user/orgs`, `/api/user/teams`, organization switching and password helper); auth-token handlers explicitly reject non-human identities with **403**. Do not interpret either as permission to mutate a service account through user endpoints. The public user API documentation broadly excludes service-account tokens; the actual reduced `/api/user` handler is an exception. [Identity checks](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/user.go), [token checks](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/user_token.go).

## Organization context and memberships

`X-Grafana-Org-Id` is a context selector, never a membership grant. In pinned authentication, a valid resource namespace takes priority; positive `orgId` / legacy `targetOrgId` query selection comes next, followed by the header. Invalid numeric values fall through rather than overriding valid earlier context. User membership and effective permissions must still be checked. A service-account token remains bound to its one organization regardless of these selectors. [Context selection](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/authnimpl/service.go).

| Route | Body / successful result | Boundary |
| --- | --- | --- |
| `GET /api/org` | **200** `{id,name,address:{address1,address2,city,zipCode,state,country}}` | Authenticated current organization, `orgs:read`. |
| `PUT /api/org` / `PUT /api/org/address` | `{name}` / address fields → **200** message | Current-org write permission. |
| `GET /api/org/users` | **200** member DTO array (`orgId,userId,uid,login,email,name,role,isDisabled,...`) | Current-org member read permission; no global-user list leakage. |
| `GET /api/org/users/search` | **200** `{totalCount,orgUsers,page,perPage}` | Pagination/search remains organization scoped. |
| `POST /api/org/users` | `{loginOrEmail,role}` → **200** `{userId,message}` | Add an existing user; absent user **404**, existing membership **409**. Role cannot exceed the caller's grant. |
| `PATCH /api/org/users/:userId` | `{role}` → **200** message | Invalid role **400**, excessive grant **403**; last organization administrator cannot be demoted (**400**). |
| `DELETE /api/org/users/:userId` | **200** message | Last organization administrator cannot be removed (**400**); clean organization-local permissions. |
| `POST /api/user/using/:orgId` | No body → **200** `{message:"Active organization changed"}` | Validate the human user's actual memberships; nonmember target **401**. Persist active organization. |
| `GET /profile/switch-org/:orgId` | Valid member → browser redirect home | Invalid/nonmember browser target returns error/absence rather than switching context. |
| `GET /api/orgs` / `GET /api/orgs/:orgId` / `GET /api/orgs/name/:name` | **200** organization array / detail | Global/cross-org permission middleware; ordinary organization Admin or SA Admin is insufficient for instance-wide enumeration. |
| `POST /api/orgs` | `{name}` → **200** `{orgId,message}` | Human identity plus create-org permission/configuration; duplicate name **409**. |
| `PUT /api/orgs/:orgId` / `PUT /api/orgs/:orgId/address` | Name/address → **200** message | Resolve permissions in the explicitly targeted organization. |
| `DELETE /api/orgs/:orgId` | **200** message | Current active organization cannot be deleted (**400**); missing target **404**. |

`/api/orgs/:orgId/users` also exposes GET/POST and PATCH/DELETE `/:userId` with the same membership bodies, but its authorization runs in that targeted organization. These are not aliases that permit bypassing current-org checks. [Organization handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/org.go), [membership handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/org_users.go), [organization models](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/org/model.go), [registration](https://github.com/grafana/grafana/blob/v13.2.3/pkg/api/api.go).

Grafana's switch handler persists the user's active organization. MetricsPanel233's current pure storage additionally scopes a browser session to its own current organization; changing one session does not move other sessions. This is an intentional design difference until a compatibility decision and browser tests establish the desired behavior. Organization dispatcher availability must remain gated until collectors, workers, datasource credentials, Live and all resource permissions resolve the same trusted organization.

## Teams

Team membership is separate from the organization's basic role. Team-admin permission controls that team; it does not grant organization Admin or instance administrator. Team DTOs include `id,uid,orgId,name,email,avatarUrl,memberCount,permission,accessControl,isProvisioned,externalUID`. [Models](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/model.go), [OSS permission actions](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/accesscontrol/ossaccesscontrol/team.go).

| Route | Request / successful result |
| --- | --- |
| `GET /api/teams/search` | `query,name,teamId,perpage,page,sort,accesscontrol` → **200** `{totalCount,teams,page,perPage}`; defaults page1/perpage1000. |
| `POST /api/teams` | `{name,email?}` → **200** `{teamId,uid,message}`; duplicate name **409**. |
| `GET /api/teams/:teamId` | **200** team DTO; malformed ID **400**, absent team **404**. |
| `PUT /api/teams/:teamId` | `{name,email}` → **200** message; duplicate updated name is **400** in the handler. |
| `DELETE /api/teams/:teamId` | **200** message; absent team **404**. A team owning folders can be blocked with **409**. |
| `GET /api/teams/:teamId/members` | **200** member DTO array; includes user/team IDs and UIDs, `email,name,login,avatarUrl,permission,labels,auth_module`. |
| `POST /api/teams/:teamId/members` | `{userId}` → **200** message; already-member **400**. Added member starts with member permission. |
| `PUT /api/teams/:teamId/members/:userId` | `{permission:0|4}` (member/admin) → **200** message; missing membership **404**. |
| `PUT /api/teams/:teamId/members` | `{members:[email...],admins:[email...]}` → **200** message; replaces the membership set after resolving organization-local users. |
| `DELETE /api/teams/:teamId/members/:userId` | **200** message; absent membership **404**. |

Reads/writes use the registered `teams:read/write/delete/create` and `teams.permissions:read/write` checks, with IDs/UIDs resolved in the caller's organization. Validate every added user belongs to that organization. Service-account management grants to teams do not make service accounts team members. Sources: [team route registration](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/teamapi/api.go), [team handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/teamapi/team.go), [membership handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/teamapi/team_members.go), [API reference](https://github.com/grafana/grafana/blob/v13.2.3/docs/sources/developer-resources/api-reference/http-api/api-legacy/team.md).

Service-account membership has an important source-level ambiguity in 13.2.3 OSS. Ordinary team-member queries explicitly pass `is_service_account=false`, so these lists hide service accounts. The legacy single-member POST delegates to `SetUserPermission`; its user validation calls `GetSignedInUser`, whose pinned SQL does not exclude service accounts. The team-member write hook likewise has no explicit service-account rejection, and signed-in identities receive their stored team IDs. This is evidence of a possible hidden service-account membership write path, not a result verified against a live Grafana 13.2.3 instance. Do not describe the pinned API as consistently rejecting service accounts, or assume the human-only list proves none exist. [Member-query filter](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/teamimpl/queries/get_team_members.sql), [team storage and hooks](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/team/teamimpl/store.go), [resource-permission user validation](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/accesscontrol/resourcepermissions/service.go), [legacy signed-in-user query](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/user/userimpl/store.go), [identity team IDs](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/user/userimpl/legacy_user.go).

MetricsPanel233's native team storage explicitly supports `{kind:"user"|"service-account",id}`. Its independent user and service-account numeric IDs must never be inferred from a bare Grafana `userId`. A future legacy adapter needs a durable shared identity mapping before it can claim compatibility with this hidden path. Each native membership has exactly one typed foreign key bound to its organization; human membership requires an active organization membership and an enabled user, and a service account must belong to that organization and be enabled. Team permissions are only Member `0` or Admin `4`. All authorization reads recheck the current state, so disabled accounts, removing organization memberships, inactive organizations and deleting teams lose effective team grants immediately. Organization-member deletion cascades the team membership, preventing an organization rejoin from reviving it. Member removal does not delete unrelated direct principal permissions.

Native team deletion first persists an immutable recovery job and marks the team `deleting` in the identity transaction. The name remains reserved until the organization resource store's team ACL cleanup is complete and `CompleteTeamRemoval` explicitly completes that job. The catalog cannot attest that a separate database transaction has run. Completed teams retain their old numeric ID and UID as tombstones; recreating the same name gets new identities and no old team membership or ACL. Member changes advance the team's revision for cache invalidation, and readded members get a fresh revision rather than reusing the removed membership's version. Native optimistic versions, typed members, timestamps in milliseconds and deletion recovery are deliberate storage contracts, not Grafana HTTP response compatibility claims.

## Service accounts and tokens

| Route | Pinned request / actual successful response |
| --- | --- |
| `GET /api/serviceaccounts/search` | `query,perpage,page,disabled,expiredTokens` → **200** `{totalCount,serviceAccounts,page,perPage}`; defaults page1/perpage1000. |
| `POST /api/serviceaccounts` | `{name,role?,isDisabled?}` → **201** SA DTO; default role Viewer, disabled false. |
| `GET /api/serviceaccounts/:id` | **200** SA DTO; organization-scoped read grant. |
| `PATCH /api/serviceaccounts/:id` | Optional `name,role,isDisabled` → **200** `{message,id,name,serviceaccount:profile}`; omitted fields preserve values. |
| `DELETE /api/serviceaccounts/:id` | **200** message; removes the account and its tokens. |
| `GET /api/serviceaccounts/:id/tokens` | **200** token DTO array, ordered by name. |
| `POST /api/serviceaccounts/:id/tokens` | `{name,secondsToLive?}` → **200** `{id,name,key}`. The key is disclosed only at creation. |
| `DELETE /api/serviceaccounts/:id/tokens/:tokenId` | **200** `{message:"Service account token deleted"}`; bind organization, account and token simultaneously. |

SA DTO fields are `id,uid,name,login,orgId,isDisabled,role,tokens,avatarUrl` with optional access-control metadata. Update's nested profile additionally has `createdAt,updatedAt,teams`. Token DTO fields are `id,name,created,lastUsedAt,expiration,secondsUntilExpiration,hasExpired,isRevoked`; they contain **neither key nor role**. The service account's current role supplies permissions, not an independent token role. `secondsToLive=0` means no expiry unless configured maximum-lifetime policies require one; negative TTL is rejected, and positive TTL uses seconds. Source expiration checking rejects `expires <= now`. Organization/token names are unique across accounts in an organization; deleting another account's token must return absence. [Actual API handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/api/api.go), [token handlers](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/api/token.go), [DTO/error models](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/models.go), [token storage](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/database/token_store.go), [expiry/uniqueness storage](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/apikey/apikeyimpl/xorm_store.go).

Handler behavior takes precedence over stale examples: the pinned legacy service-account reference shows a flattened PATCH response, a token `role` and an older token-delete message. The actual handlers above differ. Their token-comment requirement for Basic plus Grafana Admin is also superseded by the registered organization-local `serviceaccounts:read/write` permission middleware. Invalid role and duplicate SA/token names use typed **400** errors; requesting a role higher than the caller is **403**. The store's duplicate token error is not the swagger comment's **409**. [Legacy examples](https://github.com/grafana/grafana/blob/v13.2.3/docs/sources/developer-resources/api-reference/http-api/api-legacy/serviceaccount.md), [registered permissions](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/api/api.go).

A service account belongs to one organization, cannot gain server-administrator identity, cannot acquire extra organizations through human membership routes, and cannot perform instance administration even with organization role Admin. OSS user/team Edit/Admin grants can delegate management of a particular service account; Enterprise custom roles are not required to describe those grants. [Token identity](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/authn/clients/api_key.go), [OSS SA permissions](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/accesscontrol/ossaccesscontrol/service_account.go).

The native pure store deliberately keeps a stable login of `sa-ID`, case-insensitive organization-local display names and explicit write revisions. Grafana generates the initial login from organization/name normalization, so names differing only by spaces/dashes can collide there. Native revoke retains the token row and its name reservation; Grafana token DELETE removes the row. Before an HTTP compatibility claim, add the appropriate deletion adapter, UID/token-count mapping and RFC3339/null-expiration DTO conversion; do not expose native millisecond metadata as a Grafana response. [Pinned login generation](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/utils.go), [pinned token deletion](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/serviceaccounts/database/token_store.go).

## Required acceptance evidence before HTTP exposure

### Native storage additions

The internal catalog now supports partial user profile updates, global user search/lookup and versioned instance-admin changes. Login/email aliases use the same normalized keys as authentication; profile updates commit alias ownership and user metadata together. Disabling or demoting an administrator must preserve an enabled human instance administrator with at least one active membership in an active organization. Membership removal and organization disable/delete transitions need the same availability check, excluding only the affected membership or organization rather than every membership of that person. These checks do not grant organization roles or resource permissions.

Native `RotateSession` retains the device ID, current organization, original absolute expiry and idle policy. It stores only current/previous credential digests, handles the tagged seen/unseen rotation schedule and avoids a second ordinary rotation within five seconds. `AuthenticateSessionWithRotation` reports an overdue credential explicitly; rotation and logout recheck current identity state, and logout via a valid previous credential revokes the whole device. The existing request authenticator still requires the HTTP rotation gate and cookie response adapter before these helpers form a browser login workflow. Native millisecond timestamps, absolute/last-activity expiry and credential encoding remain distinct from Grafana's DTO and session representation. [Tagged rotation service](https://github.com/grafana/grafana/blob/v13.2.3/pkg/services/auth/authimpl/auth_token.go), [tagged rotation schedule](https://github.com/grafana/grafana/blob/v13.2.3/pkg/models/usertoken/user_token.go).

Membership content revisions and authorization identity are separate. A durable generation survives membership cleanup and increments on rejoin; role/profile edits preserve it. Content revisions also continue above the previous membership's final revision, so a stale version-only mutation or cleanup job cannot match a later membership. Organization-local user grants must bind the generation and compare it with current membership on every authorization decision, so an old delayed grant cannot become valid for a rejoined user. The ledger is an internal extension, not a Grafana HTTP field.
